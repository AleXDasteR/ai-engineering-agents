# MCP / Tool QA

Проверить контракты аргументов и результатов инструментов, обработку ошибок, лимиты времени и безопасность повторных вызовов.

## Запуск

Команды выполняются из корня общего репозитория. Нужен Node.js 22+.

```sh
node agents/mcp-tool-qa/run.mjs --input agents/mcp-tool-qa/example.json --output output/mcp-tool-qa.json
```

Пример [example.json](example.json) содержит синтетические данные. Результат сохраняется в JSON. Exit code 0 означает passed, 1 означает failed или review, 2 означает ошибку входных данных или запуска. Существующий отчёт сохраняется при ошибке валидации входа.

## Входные данные

`tools` содержит name, inputSchema, необязательную outputSchema, effect и retrySafe. `cases` хранит аргументы, наблюдаемый result с isError и structuredContent, ожидаемые валидность входа и статус ошибки, durationMs и attempts. `limits` задаёт пределы времени и попыток.

## Что проверяется

Проверяет записанные вызовы по схемам и ожиданиям кейса. Намеренный вызов с неверным аргументом считается успешным тестом, если инструмент вернул ожидаемую ошибку. Повтор изменяющего вызова проверяется по retrySafe и idempotencyKeyArgument.

## Работа с coding-агентом

Откройте корень репозитория и используйте [skill mcp-tool-qa](../../.agents/skills/mcp-tool-qa/SKILL.md).

> Используй mcp-tool-qa для моего проекта. Сверь исходные данные, выполни проверку и объясни результат с конкретными доказательствами.

Получи актуальные описания инструментов через доступный MCP runtime и подготовь тесты на валидный вход, неверные типы, пропущенные поля, ошибку сервера и повтор. Используй тестовые ресурсы для изменяющих инструментов. Сохрани фактические ответы, время и число попыток в формате example.json. После CLI проверь неизвестные ключевые слова полноценным валидатором нужной версии JSON Schema. Отдельно проверь подключение и обнаружение инструментов в runtime.

## Границы проверки

Поддержаны type, properties, required, additionalProperties, items, enum, const, minimum/maximum, длины строк и массивов, boolean schemas и описательные метаданные. Неподдержанные ключевые слова, включая $ref и anyOf, получают явный статус review. CLI анализирует сохранённые вызовы. Доступность сервера и протокольный обмен проверяются отдельно в разрешённой тестовой среде.
