# CI Test Agent

Агент проверяет изменения перед интеграцией. Он читает diff, выбирает релевантные проверки, разбирает причины падения и готовит вердикт. CLI предоставляет воспроизводимый gate для локального запуска и CI.

## Запуск с coding-агентом

Skill находится в [.agents/skills/ci-test](../../.agents/skills/ci-test/SKILL.md).

> Используй ci-test для проекта в C:/projects/hearth-ledger. Проверь сборку и регрессии, объясни каждое падение и укажи, что мешает интеграции.

## Локальный запуск

Из корня репозитория агентов

```powershell
node agents/ci-test/run.mjs --project "C:/projects/hearth-ledger" --plan adapters/hearth-ledger/ci.plan.json --hdt "$env:LOCALAPPDATA/HearthstoneDeckTracker/current" --output output/hearth-ledger-ci
```

Без `--base` сравниваются HEAD и рабочая папка, включая staged и untracked файлы. В репозитории без первого коммита новые файлы считаются изменениями. Для проверки уже закоммиченного PR передайте `--base <SHA>`. Флаг `--all` запускает все проверки даже при чистом рабочем дереве.

Результат записывается в `ci-test.json`. Код 1 означает failed или blocked, код 0 — passed или skipped. Проверяйте поле `status`, чтобы отличить выполненные проверки от пустой очереди. Для релиза используйте `--all`.

## Выбор проверок

В [плане Hearth Ledger](../../adapters/hearth-ledger/ci.plan.json) изменения `src/` выбирают сборку и доменные регрессии. Изменение Build.ps1 выбирает сборку. Любой неизвестный путь выбирает весь набор проверок. Неверная базовая ревизия завершает запуск ошибкой.

Каждая команда имеет timeout. Runner завершает дерево зависших процессов на Windows и группу процессов на Unix. Вывод ограничен последними 64 тысячами символов для каждого потока и помечается `truncated`, если был обрезан. Отчёт записывается через временный файл и переименование.

## Подключение к CI/CD

Для запуска в GitHub Actions используйте [пример проверки этого репозитория](../../.github/workflows/check.yml). Для внешнего продукта checkout продукта должен содержать доступную базовую ревизию. Передайте пути к проекту, плану, каталогу результатов и зависимостям.

Hearth Ledger использует зависимости HDT из локальной установки Windows. На CI-runner их нужно подготовить отдельно и передать через `--hdt`. Локальный результат подтверждает работу адаптера, а запуск этого адаптера на hosted runner требует такого окружения.

В обычном CI job исполняется CLI. Анализ причин падения выполняется skill в coding-сессии или в отдельной авторизованной agent-сессии, получающей JSON и логи.
