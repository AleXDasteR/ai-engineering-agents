# Проверка продукта

Прочитай README продукта, применимые инструкции и изменённый код. Найди обычный вход в приложение и доступные проверки. Сопоставь ожидаемое поведение с реализацией, выдели потерю данных, неверные расчёты и нарушения основного пользовательского сценария.

Составь короткий план из конкретных сценариев с ожидаемыми результатами. Переиспользуй существующие проверки, сверив их с текущими API и версией приложения. Для найденного пробела добавляй регрессионный сценарий, который воспроизводит проблему через реальный код.

Для автоматизированного этапа используй план и CLI из [README агента](../../../agents/product-qa/README.md). Запускай команды в тестовой среде с отдельным каталогом результатов. Полный traceback и вывод команды находятся в JSON-отчёте.

Для UI-сценариев открой продукт через доступный browser или computer-use runtime. Проверь текущую документацию инструмента перед действиями. Зафиксируй шаги, ожидаемый и фактический результат, снимок состояния. Отметь отдельно сценарии, для которых нужны игровая сессия, внешняя подписка или вход пользователя.

На каждую ошибку дай минимальные шаги воспроизведения, приоритет, затронутый сценарий и ссылку на источник в коде. Распознавай несовместимую версию зависимости и устаревший тест как отдельную причину сбоя. Итог должен отражать фактически выполненные проверки и оставшиеся ограничения.

Запрос на тестирование позволяет запускать проверки и писать тестовые артефакты. Изменения продукта выполняй, когда пользователь поручил исправление. Повторяй проверку после исправления и сохраняй исходный сбой в отчёте.
