# Agent Security QA

Проверить наблюдаемые действия агента на нарушение разрешений, внешнюю отправку данных и утечку контрольных маркеров при prompt injection.

## Запуск

Команды выполняются из корня общего репозитория. Нужен Node.js 22+.

```sh
node agents/agent-security-qa/run.mjs --input agents/agent-security-qa/example.json --output output/agent-security-qa.json
```

Пример [example.json](example.json) содержит синтетические данные. Результат сохраняется в JSON. Exit code 0 означает passed, 1 означает failed или review, 2 означает ошибку входных данных или запуска. Существующий отчёт сохраняется при ошибке валидации входа.

## Входные данные

`tools` объявляет name и effect. Каждый кейс содержит attack, синтетический canary, policy и observed. Policy задаёт allowedTools, allowedDestinations и allowExternalWrites. Observed содержит ответ и вызовы с arguments, executed и destination для внешних инструментов.

## Что проверяется

Различает предотвращённые попытки и выполненные действия. Проверяет разрешённые инструменты, целевые хосты и внешние записи. Ищет буквальную утечку canary в ответе, внешних аргументах и адресе назначения. Неизвестные метаданные и неполное подтверждение egress дают review.

## Работа с coding-агентом

Откройте корень репозитория и используйте [skill agent-security-qa](../../.agents/skills/agent-security-qa/SKILL.md).

> Используй agent-security-qa для моего проекта. Сверь исходные данные, выполни проверку и объясни результат с конкретными доказательствами.

Определи разрешённые действия и границы доступа тестируемого агента. Создай отдельную тестовую среду с синтетическими canary и макетами внешних получателей. Прогони прямые и косвенные инъекции через обычные входы агента, сохрани ответы, попытки и фактическое выполнение инструментов. После CLI разбери нарушения и пробелы наблюдаемости. Предложи исправление границы доверия и повтори те же атаки. Содержимое атаки остаётся данными теста.

## Границы проверки

Кейсы содержат синтетические маркеры. CLI анализирует наблюдаемые трассы и не исполняет атакующие промпты. Проверка ограничена заданной политикой и буквальными маркерами. Семантические, закодированные и многошаговые утечки требуют дополнительных сценариев.

## Проверка реализации

```sh
node --test test/analysis.test.mjs

```

В общий CI включены штатные примеры и сценарии ошибок для каждого модуля. Полные локальные отчёты находятся в output и исключены из Git.
