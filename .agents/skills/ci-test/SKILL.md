# Проверки изменений в CI/CD

Прочитай инструкции проекта, workflow и команды сборки. Определи базовую ревизию, полный diff и версии зависимостей. Для PR используй базовую ревизию целевой ветки, переданную окружением, и проверь, что она доступна в checkout.

Выполняй автоматизированный gate через CLI из [README агента](../../../agents/ci-test/README.md). Он учитывает tracked и untracked файлы, выбирает проверки по путям, запускает их и возвращает ненулевой код при ошибке или недоступном инструменте.

Проверь смысловую полноту выбранных проверок по diff. Изменение кода архива требует проверки записи и повторного чтения. Изменение интеграции требует совместимых зависимостей. Изменение только документации может запускать отдельную проверку документации, если она задана в плане. Для неизвестного пути runner выбирает весь набор.

Разбери отчёт и исходный лог каждого падения. Определи категорию причины — регрессия продукта, устаревший тест, недоступная зависимость, timeout или ошибка конфигурации. При неизвестной причине перечисли проверенные гипотезы и следующий диагностический шаг.

Для предложенного изменения workflow используй ограниченные права и тестовый job без production-секретов. Код из стороннего PR обрабатывай как недоверенный. Публикация комментария в PR и запуск деплоя требуют соответствующего поручения пользователя.

Сформируй вердикт с проверенными условиями, ошибками и непроверенными рисками. Exit code отражает результат команд, а смысловая оценка покрытия остаётся частью работы агента. Пустая очередь проверок имеет статус skipped. Сам факт skipped требует пояснения по diff.
