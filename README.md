# AI Engineering Agents

Набор агентов для повседневной работы AI-инженера. Каждый агент содержит skill для coding-сессии, документацию запуска и проверяемые результаты. Повторяемые проверки вынесены в исполняемые CLI.

| Агент | Задача | Инструкция |
| --- | --- | --- |
| Job Search | Поиск вакансий, проверка критериев и дублей, подготовка писем | [README](agents/job-search/README.md) |
| Product QA | Проверка пользовательских сценариев и воспроизведение ошибок | [README](agents/product-qa/README.md) |
| CI Test | Выбор проверок по diff, сборка, регрессии и вердикт | [README](agents/ci-test/README.md) |
| LLM Eval | Сравнение моделей по эталонным ответам, цене и задержке | [README](agents/llm-eval/README.md) |
| RAG QA | Retrieval, цитаты, свежесть документов и отказ от ответа | [README](agents/rag-qa/README.md) |
| MCP / Tool QA | Контракты входа и выхода, ошибки и повторы вызовов | [README](agents/mcp-tool-qa/README.md) |
| AI Cost Monitor | Расходы, кэш, задержки и регрессии стоимости | [README](agents/ai-cost-monitor/README.md) |
| Incident Triage | Группировка ошибок, доказательства и гипотезы | [README](agents/incident-triage/README.md) |
| Agent Security QA | Политика доступа, prompt injection и canary-утечки | [README](agents/agent-security-qa/README.md) |

## Быстрый запуск

Нужен Node.js 22+. Внешние npm-пакеты для CLI отсутствуют. Все команды запускаются из корня этого репозитория.

    node --test
    node scripts/demo-agents.mjs
    node agents/ci-test/run.mjs --project . --plan examples/ci.plan.json --all --output output/ci

Последняя команда запускает собственный CI gate репозитория и сохраняет JSON-отчёт. Job Search demo запускается командой npm run demo. Для Hearth Ledger потребуются Windows, .NET Framework и установленный Hearthstone Deck Tracker. Готовые планы находятся в adapters/hearth-ledger.

## Использование skills

Откройте эту папку как проект в Codex или совместимом coding-агенте. Skills находятся в .agents/skills. Для каждого нового агента пример запроса, команда запуска и формат результата приведены в его README.

Агент читает требования и код, выбирает сценарии, выполняет проверки через CLI и UI-инструменты и объясняет результат. CLI тестовых агентов запускает команды из плана, ограничивает время работы, сохраняет доказательства и возвращает код выхода для CI. Шесть аналитических CLI обрабатывают снимки наблюдений. Подготовка реальных измерений и смысловая оценка результатов описаны в skills.

Полный локальный прогон содержит 58 проверок и три CI-проверки. Происхождение данных и границы измерений приведены в [отчёте проверки набора](reports/agent-suite-2026-11-21.md).

## Проверка на настоящем продукте

Product QA и CI Test прогнаны на плагине Hearth Ledger. Сборка с HDT 1.60.7 прошла, в доменных сценариях обнаружено игнорирование исправленного режима матча. Есть [отчёт с воспроизведением](reports/hearth-ledger-2026-11-21.md) и адаптер, использующий реальные исходники продукта. Проверка оверлея в живой партии остаётся отдельным сценарием.

## Структура

- .agents/skills — инструкции для трёх агентов.
- agents — README каждого агента и CLI тестовых агентов.
- lib — запуск проверок, выбор по изменениям и запись отчёта.
- adapters/hearth-ledger — планы и тестовый harness внешнего продукта.
- src, examples — модуль и демонстрационные данные Job Search. Его прежний CLI сохранён для существующих запусков.
- test — регрессионные проверки кода репозитория.
- reports — обезличенные результаты фактических прогонов.
- output — локальные логи и артефакты, исключённые из Git.

## Вклад и происхождение

Исходный личный Job Search workflow был создан для поиска работы в Claude Code, затем адаптирован для Codex. Публичная версия и тестовые агенты оформлены 21 ноября 2026 совместно с Codex. Репозиторий показывает постановку задач, управление coding-агентом, проверку результатов и итерации по найденным ошибкам.

Полные личные журналы откликов и рабочие проекты под NDA хранятся отдельно. Примеры вакансий синтетические, а отчёт по Hearth Ledger основан на выполненных проверках.

## Добавление агента

Для выбранной задачи добавьте skill, README с входными данными и командой запуска и воспроизводимый пример. Общий runner используйте для проверок, которым подходят запуск процесса, timeout и JSON-отчёт. Новые предметные сценарии размещайте рядом с соответствующим агентом или адаптером.

Идеи следующих агентов обсуждаются до реализации. Это позволяет проверять каждый добавленный workflow на конкретной рабочей задаче.
