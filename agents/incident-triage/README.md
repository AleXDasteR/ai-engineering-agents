# Incident Triage

Сгруппировать сигналы сбоя, сохранить доказательства, подготовить проверяемые гипотезы и следующие диагностические шаги.

## Запуск

Команды выполняются из корня общего репозитория. Нужен Node.js 22+.

```sh
node agents/incident-triage/run.mjs --input agents/incident-triage/example.json --output output/incident-triage.json
```

Пример [example.json](example.json) содержит синтетические данные. Результат сохраняется в JSON. Exit code 0 означает passed, 1 означает failed или review, 2 означает ошибку входных данных или запуска. Существующий отчёт сохраняется при ошибке валидации входа.

## Входные данные

`events` содержит timestamp с часовым поясом, service, level, message и необязательный traceId. Допустимые уровни — debug, info, warn, error и fatal.

## Что проверяется

Группирует ошибки по сервису и наблюдаемой сигнатуре. Выделяет проблемы диска, ограничения запросов, авторизации, соединения и timeout. Сохраняет до пяти примеров на группу, считает события и определяет временные границы независимо от порядка входа.

## Работа с coding-агентом

Откройте корень репозитория и используйте [skill incident-triage](../../.agents/skills/incident-triage/SKILL.md).

> Используй incident-triage для моего проекта. Сверь исходные данные, выполни проверку и объясни результат с конкретными доказательствами.

Зафиксируй временное окно, сервисы, симптомы и последнюю успешную версию. Собери разрешённые логи и метрики, сохрани ID событий для воспроизведения. После CLI проверь каждую гипотезу по конфигурации, зависимостям и изменённому коду. Отличай наблюдаемый факт от объяснения. Для подтверждённой причины предложи минимальное исправление и проверку восстановления. Выполняй изменения и внешние уведомления только в рамках поручения пользователя.

## Границы проверки

Причины помечаются как гипотезы. Известные сообщения помогают выбрать проверку, окончательную причину подтверждает диагностика. Маскирование покрывает распространённые присваивания credentials, Bearer, пароли в URL и почту. Перед внешней публикацией лог требует проверки. Наличие инцидентов или пустой набор возвращает review.
