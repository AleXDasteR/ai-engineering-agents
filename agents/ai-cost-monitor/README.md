# AI Cost Monitor

Найти рост стоимости, задержек и ошибок в потоке LLM-запросов с учётом кэшированных входных токенов.

## Запуск

Команды выполняются из корня общего репозитория. Нужен Node.js 22+.

```sh
node agents/ai-cost-monitor/run.mjs --input agents/ai-cost-monitor/example.json --output output/ai-cost-monitor.json
```

Пример [example.json](example.json) содержит синтетические данные. Результат сохраняется в JSON. Exit code 0 означает passed, 1 означает failed или review, 2 означает ошибку входных данных или запуска. Существующий отчёт сохраняется при ошибке валидации входа.

## Входные данные

`baseline` и `current` задают длительность окна seconds и массив requests. У запроса нужны id, model, inputTokens, outputTokens, latencyMs и success, опционально cachedInputTokens. `pricesUsdPerMillion` и `budgets` задаются явно.

## Что проверяется

Считает стоимость каждого запроса, стоимость на запрос, прогноз за час, p95, долю ошибок и распределение расходов по моделям. Рост сравнивается на один запрос, чтобы отделить изменение цены от увеличения трафика.

## Работа с coding-агентом

Откройте корень репозитория и используйте [skill ai-cost-monitor](../../.agents/skills/ai-cost-monitor/SKILL.md).

> Используй ai-cost-monitor для моего проекта. Сверь исходные данные, выполни проверку и объясни результат с конкретными доказательствами.

Сверь период, workload и тарифы сравниваемых окон. Раздели uncached и cached usage по фактической схеме провайдера. Проверь, что запросы с ошибками включены в расходы с наблюдаемым usage. После CLI разбери, вызван ли рост моделью, длиной контекста, кэшированием, повторными попытками или изменением состава задач. Предлагай оптимизацию с последующим замером качества.

## Границы проверки

inputTokens включает кэшированные токены. Для cachedInputTokens требуется цена cachedInput. Прогноз за час предполагает сохранение текущего темпа. Цены и окна предоставляет пользователь, данные demo-model условные. Изменение качества задач и нагрузки требует отдельного анализа.
